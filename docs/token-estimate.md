# 剩余 Token 估算

`≈ … 词元` 表示：延续近期各会话的模型、缓存、输出及 Fast 使用组合，预计还可使用多少实际 Token。它不表示官方返回的 Token 余额，也不假设所有会话以后都关闭 Fast。

## 官方依据

费率表核验于 **2026-09-07**：

- [各模型 Token / Credits 费率](https://learn.chatgpt.com/docs/pricing#token-rates)
- [ChatGPT Work / Codex credit rate card](https://help.openai.com/en/articles/11481834-chatgpt-rate-card-business-enterpriseedu-credit-based-pricing)
- [Fast 模式倍率](https://learn.chatgpt.com/docs/agent-configuration/speed)
- [套餐额度与额外购买 credits 的区别](https://help.openai.com/en/articles/12642688-using-credits-for-flexible-usage-in-chatgpt-freegopluspro-sora)

普通输入、缓存输入和输出分别计算参考成本，再应用该次调用的 Fast 倍率。rollout 的 `input_tokens` 已包含 `cached_input_tokens`，因此普通输入为两者之差；`output_tokens` 已包含推理输出，不能再加一次 `reasoning_output_tokens`。例如 GPT-5.5 的 20,000 普通输入、80,000 缓存输入和 5,000 输出，参考成本为 7.25 credits。

费率表中的购买 credits 价格不能直接当作套餐内额度容量。官方特别说明 Sol 的促销不改变套餐内 5 小时和每周限制，因此费率只用于估算调用的相对成本，额度容量必须由实际百分比变化校准。参考费率集中维护在 `CodexCreditRateCard`，未列出的模型、无法确认的模型别名及无明细的历史记录不猜价格。

## 计算过程

1. 复用本机 rollout 增量扫描与 Fork / 子代理去重，只保留最近一周附近的数值用量和额度快照。第三方 provider 和 API-key 模式不参与 ChatGPT 额度估算。
2. 匹配当前额度桶、套餐和周期长度，按 `resets_at` 将各周期单独校准。当前周期有足够样本时优先使用当前容量，否则参考近期同套餐的已校准周期；不跨重置相减百分比，也不把重置前的消耗带入新周期。
3. 按时间合并所有本机会话。对跨度至少 **5 个百分点**的区间，累计期间的参考成本；取多个区间容量的加权中位数，降低百分比取整、延迟快照及异常区间的影响。
4. 使用最近 **7 天以内、匹配额度桶及套餐**的调用计算参考成本 / 实际 Token。采用 **3 天半衰期**，近期调用权重更高；空闲日不会被补成零来缩小额度容量。
5. 用校准容量乘以剩余比例，再除以近期每 Token 参考成本。多个有效额度窗口同时存在时，取预计剩余 Token 较少的一项。

```text
区间推算的总容量 = 区间参考成本 ÷ 已用额度百分点增量 × 100
近期单位成本 = Σ(调用参考成本 × 时间权重) ÷ Σ(实际 Token × 时间权重)
预计剩余 Token = 校准总容量 × 剩余比例 ÷ 近期单位成本
```

## 显示条件与边界

- 至少有 10 次可定价调用、两个各跨至少 5 个百分点的有效校准区间；总体及各区间可定价 Token 覆盖率至少为 90%。缺失 Token 明细和未知模型降低覆盖率。
- 重置后可参考近期历史容量，提示中会说明；当前周期样本充足后优先使用当前校准。套餐变化不会借用其他套餐的样本；运行中收到已知账户的变更通知后，只使用通知后的记录。数据不足、窗口过期或其他有效额度窗口无法校准时显示“—”。任一有效窗口耗尽时显示 0。
- 与图表的服务端 / 本地日用量合并独立，不再对服务端原始 Token 与本地 Fast 等效 Token 取最大值后用于推算容量。
- 只使用本机可见记录。其他设备、云端任务、共享额度的其他产品、读取失败或未完整保留的日志可能造成偏差；可定价覆盖率不代表完整的账户活动覆盖率。
- 费率促销、模型组合和缓存比例改变后，估算仍可能与实际额度消耗不同；本数值用于用量参考，不是账单核算。
- 数值样本随现有内存缓存保留，估算最多每 30 秒重新校准一次；额度快照变化时立即重新计算，不增加历史文件扫描频率或写入用户日志。

## 会话累计 credits

会话 Token 明细弹层在累计 Token 数后显示金色 `(55.2 credits)`。直接使用官方公式：`((Input − Cache) × 普通输入费率 + Cache × 缓存费率 + Output × 输出费率) ÷ 1,000,000`，再乘该次调用的 Fast 倍率。Input 已含缓存、Output 已含推理，因此不会重复计价。

按会话历史各次调用的模型和已记录的 Fast 设置分别求和，最后统一保留一位小数；未记录档位时按 Standard 估算并在提示中说明。不使用当前配置追溯计价。价格采用上方核验日期的官方费率，表示参考消耗，不代表实际扣费。

credits 与弹层中的累计 Token 使用同一范围：保留日志中属于该累计计数的历史，计数重置时同步重置。重复通知不重复计费；未知模型、第三方 provider、缺失明细或无法归属的累计跳增显示 `— credits`。每个会话首次读取历史后仅增量读取，缓存不保留对话内容。


## 图表历史 credits

30 日和 48 小时图表复用本机历史日志的逐次调用计价，不要求日志产生于安装此功能之后。按每次调用记录的模型、缓存、输出和 Fast 档位计算，再按天或小时汇总。

账户日 Token 可包含其他电脑的用量；credits 独立按本机日志折算，不要求两者 Token 数相等。本机调用均可计价时，词元模式在括号内显示额度数值 `(1234.6)`，跨设备差额不会添加 ≥。仅当本机调用自身缺少费率或明细时，才显示已知小计 `(≥1234.5)`，下限向下保留一位小数。悬停说明额度仅包含本机用量。完全没有本地明细的账户历史显示 `(—)`，不会按当前模型的价格套算其他电脑的历史。

## 剩余 credits 切换

额度右侧的 Tokens / Credits 切换会记住选择。剩余 credits 按项目指定的 Plus 2,750、Pro 5X 13,750、Pro 20X 55,000 乘以当前主额度剩余比例显示；这是固定基准估算，与上方按实际额度变化校准的剩余 Token 估算独立。未知套餐倍数时不猜测。两种剩余估算前均显示白色 `≈`，credits 数值为金色。


## 柱图的 Tokens / Credits 模式

中文标签为“词元 / 额度点”，英文为“Tokens / Credits”。顶部切换同步控制剩余额度数值和下方的 30 日 / 48 小时柱图。Token 模式保留“实际 / ⚡等效”。Credits 模式使用本机逐次调用的费用，图例为“标准 / ⚡实际”：标准是不开启 Fast 时的费用，实际是包含标准费用和 Fast 加价的总消耗；实际 − 标准代表开启 Fast 浪费的额度。

两项同时显示时，实心柱为标准费用，空心轮廓为实际总消耗，两者不相加；只显示实际时仍展示包含标准的总量，只显示标准时展示未开启 Fast 的费用，并按可见系列重新缩放。标准和实际费用各自保留完整精度后汇总，显示时才保留一位小数。额度切换不影响原始 Token 统计。

中文界面的 credits 单位统一显示为“额度点”。数值为 0 时显示“0”，其余数值保留一位小数。

会话列表也跟随词元 / 额度点模式切换，额度点模式显示本会话累计额度数值。悬浮明细统一使用“累计消耗”：词元模式显示“实际词元（额度点）”，额度点模式显示“额度点（实际词元）”，并保留两种数值的单位。
